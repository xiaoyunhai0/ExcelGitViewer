# Release notes

Create one Markdown file named after each release tag, for example `v0.1.6.md`.
The release workflow uses that file as the GitHub Release description. If the file is missing,
GitHub-generated notes are used as a fallback.

Keep English first and Simplified Chinese second so the release page matches the README language
order. Describe user-visible changes, important limitations, and upgrade notes rather than listing
internal commits.
